# Page override — X 수집 대시보드 (`/`, `/xconda`)

> `design-system/xconda/MASTER.md`의 규칙을 이 페이지에서만 덮어씁니다.

## 목적
운영자가 하루 몇 번 열어 "지금 상태가 정상인가 / 손봐야 할 항목이 있는가"를 5초 안에 판단한다.
관제실 성격이므로 **밀도와 스캔 속도**가 미학보다 우선한다.

## 화면 순서 (고정)
1. **페이지 헤더** — 제목 + 한 줄 설명 + 액션(`지금 실행`, `공지 페이지`)
2. **설정 경고 배너** — 미설정 항목이 있을 때만. 어떤 값이 비었는지 배지로 나열하고 다음 행동을 안내.
3. **자동 실행 경고 배너** — 조건: 기록 없음 / 6시간 이상 미실행 / 마지막 로그에 오류. 반드시 `지금 실행` 버튼을 동반한다.
4. **파이프라인 꺼짐 안내** — `enabled=false`일 때만, 설정 위치(`#x-settings`)로 링크.
5. **상태 카드 5개** — Notion / Gemini / 파이프라인 / 관제 계정 / 이미지 보관.
   - 값 텍스트가 상태를 말로 표현(`연결됨`, `미설정`, `오류`)하고 점은 보조.
   - 문제가 있으면 힌트가 원인과 해결 방법을 말한다.
   - 파이프라인 카드 하단에 `마지막 실행: 4분 전`을 항상 표기한다(기록이 없으면 `기록 없음`).
   - Notion 카드 하단에 누락 속성이 있으면 `누락 속성 추가` 폼을, 없으면 `속성 이상 없음`을 표기한다.
6. **2단 그리드** — 좌측(2/3): URL 수집 → 수집 항목 / 우측(1/3): X 수집 설정 → 관제 계정 → 운영 정보.

## 수집 항목 리스트 규칙

### 찾기 (전부 서버 렌더 · JS 없이 동작 · URL로 공유)
- **검색**은 GET 폼(`?q=`), **정렬**과 **상태 필터**는 링크 칩. 현재 검색·정렬·상태는 서로를 지우지 않고 유지된다.
- 정렬 기본값(`최신순`)과 조회 기본값(100건)은 URL에 남기지 않는다 — 주소가 짧아야 공유가 쉽다.
- 상태 필터 칩의 카운트는 **현재 검색어 기준**으로 다시 계산하고, `aria-current="true"`로 선택 상태를 노출한다.
- 조회 범위를 화면에 항상 명시한다: 툴바에 `Notion에서 최근 N건까지 조회했습니다`, 하단에 `현재 N건까지 불러왔습니다 · 100건씩 최대 500건`.
- `더 보기`는 커서를 따라 100건씩 늘리는 링크(`?limit=200`)다. 마지막 페이지면 `더 불러올 항목이 없습니다`로 바뀐다.
- 검색 결과가 0건이면 `“검색어”에 해당하는 항목이 없습니다` + `검색·필터 초기화` + (남은 페이지가 있으면) `다음 100건 더 보기`를 함께 준다.

### 카드 한 건의 정보 순서 (위 → 아래)
1. 상태 배지 · 카테고리 · 발행일 · 작성자 · **수집 시각(상대 표기)**
2. 제목
3. **상태별 다음 행동 한 줄** (`STATUS_NEXT`) — "무엇을 눌러야 하는지"를 문장으로. 배지 색만으로 판단하게 두지 않는다.
4. 요약 2줄(`line-clamp-2`)
5. `note` — 실패 상태면 로즈색, 그 외에는 muted
6. 접히는 상세(`<details>`): 요약 전문 / 공지문 / 원문
   - `<summary>`는 한 줄 높이(`min-h-9`)를 지키고 펼치기·접기 라벨을 텍스트로 제공
   - 원문은 **700자 미리보기 + 전체 길이 표기**(`700자 / 전체 3,912자`)
7. 실패 항목이면 **본문 직접 붙여넣고 재요약** 폼(복구 동선)
8. 태그 · `원문` · `공지`(Landing URL) · `Notion` 링크
9. 행 액션: 게시(primary, `SUMMARIZED`/`READY`만) · 다시 처리(secondary) · 제외(ghost)

### 상대 시간 표기
- `formatRelativeKst()`를 쓴다: `방금 전 / N분 전 / N시간 전 / N일 전`, 30일 이상이면 절대 날짜(`2026.10.02`).
- 항상 `title` 또는 괄호로 **정확한 KST 시각**을 함께 제공한다(상대 표기만 두지 않는다).
- 목록의 발행일은 날짜만(`YYYY.MM.DD`), 운영 정보의 마지막 실행은 상대 + 절대를 함께 쓴다.
- 서버 렌더에서 `Date.now()`를 컴포넌트 안에서 직접 부르지 않는다 — `src/lib/time.ts`의 `elapsedMs()`/`formatRelativeKst()`를 쓴다.

### 액션 후 되돌아오기
- 모든 폼은 hidden `back` 필드로 현재 목록 URL(검색·정렬·필터·조회 범위)을 보낸다.
- 서버 액션은 `back`이 `/`로 시작하는 내부 경로일 때만 사용하고, 아니면 `/`로 돌아간다(외부 URL 차단).
- 결과는 `?msg=`/`?err=`로 표시한다(Flash). 실패 상태를 유발한 액션은 `err`로 보낸다.

## 운영 정보 패널 (우측 하단)
- 마지막 자동 실행: 상대 시간 + 절대 시각
- 마지막 실행 로그 2줄(`x_last_tick_log`) — 오류가 포함되면 로즈색
- 자동 게시 on/off, 현재 조회 범위
- 크론 호출 안내 문장 1개(외부 크론 `/api/cron`, 1분 간격)

## 밀도 규칙
- 카드 간격 `gap-4`, 패널 간격 `gap-6`, 리스트 행 `py-4`.
- 한 화면(1024px)에서 상태 카드 + URL 수집 폼 + 수집 항목 3~4행이 함께 보이도록 유지한다.
- 설명 문구는 `text-xs leading-5`로 제한하고 2줄을 넘기지 않는다.
- 툴바는 검색 + 정렬 / 상태 필터 + 조회 범위의 **2줄**로 고정한다(줄이 더 늘어나면 밀도가 무너진다).

## 하지 말 것
- 상태 카드에 그래프·스파크라인을 넣지 않는다(신뢰할 수 있는 이력 데이터가 없음).
- 실시간처럼 보이는 장식(깜빡이는 라이브 점, 자동 갱신 카운터)을 쓰지 않는다.
  실제 갱신 주기(cron 15분/60초 tick)를 문장으로 밝힌다.
- 검색·정렬·더 보기를 JS 클라이언트 상태로 만들지 않는다. URL이 곧 상태다.
- 조회 범위를 숨기지 않는다. "왜 안 보이는지"를 운영자가 알 수 있어야 한다(100건 → 더 보기 → 500건).
