0 이 서비스는 무엇인가요?

“메일 발송 담당 직원”이 하나 생겼다고 생각하시면 됩니다. 시트는 작업 지시서, 웹 화면은 관제실입니다.

📄
① 구글 시트 보낼 메일의 날짜·제목·내용을 한 줄씩 적습니다.
🔄
② 서비스가 읽음 웹 화면에서 “시트 불러오기”를 누르면 내용이 들어옵니다.
👀
③ 미리보기·테스트 실제 메일 모양을 확인하고 내 주소로 1통 보내봅니다.
🚀
④ 자동 발송 스위치를 켜두면 적어둔 시각에 구독자에게 나갑니다.

시트에 쓰기 → 불러오기 → 테스트 → 자동 발송 켜기. 이 네 가지만 기억하시면 됩니다. 이후에는 시트에 새 줄만 추가하시면 서비스가 알아서 발송합니다.

1 3분 요약 — 이것만 알아도 발송됩니다

처음 쓰실 때 이 순서 그대로 따라 하시면 됩니다.

  1. 구글 시트 첫 줄(머리글)을 확인합니다

    1행에 발송일시 제목 본문 링크 이미지 수신자 사용 이 있어야 합니다. 2행부터 한 줄에 메일 한 통을 적습니다. 제목만 필수입니다.

  2. 시트 공유가 “링크가 있는 모든 사용자 – 뷰어”인지 확인합니다

    시트 우측 상단 공유 → 일반 액세스 → 링크가 있는 모든 사용자 → 역할 뷰어. 이게 빠지면 서비스가 시트를 못 읽습니다.

  3. 관리 화면 홈에서 🔄 시트 불러오기 를 누릅니다

    표에 방금 쓴 내용이 줄 단위로 나타납니다. 안 보이면 저장이 안 됐거나 제목 칸이 비어 있는 경우입니다.

  4. 미리보기 로 모양 확인 → 테스트 로 내 메일함에 1통 받아봅니다

    테스트 메일은 제목 앞에 [테스트]가 붙어 오고, 구독자에게는 절대 가지 않습니다. 받을 주소는 설정의 테스트 수신 이메일에 미리 넣어두세요.

  5. 홈 좌측 상단 자동 발송 카드를 켜기 로 바꿉니다

    이제 서비스가 1분마다 시트를 다시 읽고, 시간이 된 메일을 자동으로 보냅니다. 지금 당장 보내려면 해당 줄의 지금 발송을 누르세요.

한 줄 = 메일 한 통. 아래 예시처럼 채우시면 됩니다.

발송일시제목본문링크이미지수신자사용
2026-10-05 09:00 {{이름}}님, 10월 첫 소식입니다 안녕하세요! 10월 업데이트를 전해드립니다. https://example.com/news (비움) (비우면 전체) Y
(비우면 대기열) 주간 팁 #1 — 스팸함 피하는 법 **굵게** 와 줄바꿈이 그대로 적용됩니다. https://example.com/tips https://…/banner.png (비움) Y
(비움) 구독 감사 이벤트 (초안) 아직 작성 중입니다. (비움) (비움) a@x.com, b@y.com 보류

세 번째 줄처럼 사용 칸에 보류를 적으면 초안 상태로 두고 발송되지 않습니다.

열(칸)별 작성 규칙

열어떻게 쓰나요
발송일시선택 적어둔 한국시간에 발송됩니다. 2026-10-05 09:00, 2026. 10. 5 오전 9:00:00, 10/5/2026 9:00 AM 모두 인식합니다.
· 날짜만 쓰면 설정의 기본 발송 시간(예: 09:00)에 나갑니다.
· 비워두면 “대기열”로 들어가, 지정한 요일마다 위에서부터 하루 1건씩 순서대로 나갑니다.
제목필수 이 칸이 비어 있으면 그 줄은 아예 무시됩니다. {{이름}}을 쓰면 받는 분 이름으로 자동 치환됩니다.
⚠ 제목에 쉼표(,)가 있어도 반드시 한 칸(셀) 안에 넣어주세요. 옆 칸으로 밀리면 내용이 어긋납니다.
본문선택 줄바꿈은 그대로, 빈 줄은 문단 구분으로 표시됩니다.
· **중요** → 중요 (굵게)
· https://… 를 그냥 쓰면 자동으로 링크가 됩니다
· {{이름}} 치환 가능 · HTML 태그를 직접 쓰셔도 그대로 적용됩니다
링크선택 메일 하단에 “자세히 보기 →” 버튼으로 들어갑니다. 주소 하나만 넣어주세요.
이미지선택 메일 최상단 배너로 들어갑니다. 인터넷에 공개된 이미지 주소(https://…) 또는 구글 드라이브 공유 링크를 붙여넣으세요. 가로 600px 이상 권장.
· 구글 드라이브: 파일을 ‘링크가 있는 모든 사용자 – 뷰어’로 공유한 뒤 공유 링크를 그대로 붙여넣으면 됩니다. 시스템이 메일에 보이는 주소로 자동 변환합니다.
공유 설정이 안 되어 있으면 동기화할 때 경고가 표시됩니다.
수신자선택 비우면 전체 구독자에게 발송됩니다. 특정인에게만 보낼 땐 a@x.com, b@y.com 처럼 쉼표로 나열하세요.
수신거부한 분은 여기에 적어도 발송되지 않습니다.
사용선택 비워두면 발송함. 발송을 막으려면 N NO X 0 아니오 보류 중지 제외 미사용 중 하나를 적으세요.
✅ 열 이름은 조금 달라도 인식합니다

발송일시 = 발송시간 · 예약일시 · 날짜 / 제목 = 메일제목 · subject / 본문 = 내용 · body / 수신자 = 받는사람 · 이메일 / 사용 = 사용여부 · 활성 … 처럼 흔한 표현은 자동으로 알아봅니다. 다만 순서와 이름은 예시대로 두시는 게 가장 안전합니다.

⚠ “대기열”이 헷갈리실 때

발송일시를 비워두면 = “날짜는 알아서 정해줘” 라는 뜻입니다. 설정에서 정한 요일(기본 월~금)과 시간(기본 09:00)에 시트 위에서부터 하루 한 건씩 차례로 나갑니다. 특정 날짜에 꼭 보내야 하는 메일은 발송일시를 직접 적어주세요.

3 발송 4단계 (관리 화면)

홈 화면 콘텐츠 · 발송 에서 모두 처리됩니다.

STEP 1 · 불러오기

🔄 시트 불러오기 클릭 → 시트 내용이 목록에 표시됩니다.

시트를 수정하셨다면 항상 다시 눌러주세요. (자동 발송이 켜져 있으면 1분마다 자동으로 다시 읽습니다.)

STEP 2 · 미리보기

미리보기 클릭 → 실제 메일 디자인이 새 탭으로 열립니다.

이미지·버튼·줄바꿈이 의도대로 나오는지 확인하는 단계입니다.

STEP 3 · 테스트 발송

테스트 클릭 → 설정에 등록한 내 주소로만 1통 갑니다. 제목에 [테스트] 표시.

구독자에게는 나가지 않으니 마음껏 확인하세요.

STEP 4 · 발송

예약 발송: 홈 상단 자동 발송을 켜기.
즉시 발송: 해당 줄의 지금 발송.

즉시 발송은 확인 팝업에서 “몇 명에게 보낼지” 알려드립니다.

목록에 있는 버튼들

버튼하는 일
🔄 시트 불러오기구글 시트를 지금 다시 읽어 목록을 최신화합니다. (발송은 하지 않음)
⏱ 스케줄러 지금 실행1분 주기를 기다리지 않고 “보낼 게 있는지” 즉시 점검합니다. 예약 시간이 지난 건이 있으면 바로 발송됩니다.
미리보기완성된 메일 화면을 새 탭에서 보여줍니다.
테스트설정에 등록한 테스트 주소로 1통 발송합니다.
지금 발송 / 재발송예약 시간과 무관하게 즉시 발송합니다. 이미 보낸 건은 “재발송”으로 표시됩니다.
대기로발송 완료·실패한 건을 다시 대기 상태로 되돌립니다. (재시도할 때)

구독자

받는 분 명단을 관리합니다. 직접 입력 추가, 시트에서 일괄 동기화, 개별 중지 / 재개 / 삭제가 가능합니다. (자세한 내용은 6번 항목)

발송 기록

최근 300건의 발송 이력이 “언제 / 어떤 제목 / 누구에게 / 성공·실패” 형태로 남습니다. “메일이 갔나요?”에 대한 답은 항상 이 화면에 있습니다.

설정

시트 주소, 기본 발송 요일·시간, 보내는 사람 이름, 테스트 수신 주소를 정합니다. (자세한 내용은 7번 항목)

예약됨발송 시각을 기다리는 중 (정상)그냥 두시면 됩니다.
대기대기열에 있어 순서를 기다리는 중먼저 보내려면 시트에서 위쪽 행으로 옮기거나 지금 발송.

기한 지남예약 시각이 6시간 이상 지나 자동 발송 대상에서 빠짐여전히 보내려면 지금 발송, 아니면 시트에서 날짜를 새로 지정.
왜 6시간이 지나면 안 보내나요?

서버가 잠시 멈췄다가 며칠 뒤 되살아났을 때, 지난 메일이 한꺼번에 쏟아지는 사고를 막기 위한 안전장치입니다. 짧은 점검(6시간 이내)은 복구 후 정상 발송됩니다.

6 구독자 관리

받는 분을 넣는 방법은 3가지입니다.

방법설명
① 직접 입력구독자 → “구독자 추가” 칸에 한 줄에 한 명씩. hong@example.com, 홍길동 또는 홍길동 <hong@example.com> 형식 모두 가능합니다. 이미 있는 주소는 중복 등록되지 않습니다.
② 시트에서 가져오기같은 구글 파일에 ‘구독자’ 탭을 만들고 이메일, 이름 열을 채운 뒤, 그 탭을 연 상태의 URL을 설정 → 구독자 시트 URL에 넣습니다. 이후 동기화 때 자동 등록됩니다.
③ 시트의 ‘수신자’ 칸특정 메일만 몇 명에게 보낼 때. 명단에 영구 등록되지는 않습니다.
🔒 수신거부는 되돌릴 수 없습니다 (의도된 정책)

구독자가 메일 하단 수신거부를 누르면 수신거부 상태가 되고, 시트에 그 사람을 다시 적어도 자동으로 살아나지 않습니다. 법적 문제(스팸 규제)를 피하기 위한 장치이니, 되살리실 땐 반드시 본인 동의를 받은 뒤 화면에서 재개를 눌러주세요.

8 꼭 지켜야 할 규칙 5가지

사고는 거의 대부분 아래 5가지에서 발생합니다.

  1. 한 번 나간 메일은 다시 나가지 않습니다 — 단, 제목·발송일시를 고치면 “새 메일”이 됩니다

    오타를 고치려고 이미 발송된 줄의 제목을 수정하면 시스템은 이를 새 콘텐츠로 보고 다시 발송합니다. 발송이 끝난 줄은 가급적 건드리지 마시고, 수정이 필요하면 새 줄을 추가해 주세요.

  2. 모든 시간은 한국시간(KST)입니다

    서버가 해외에 있어도 시트에 적은 시각 그대로 한국시간 기준으로 나갑니다. 별도 시차 계산이 필요 없습니다.

  3. 시트를 고쳤으면 “불러오기”

    자동 발송이 꺼져 있을 때는 화면이 자동으로 갱신되지 않습니다. 🔄 시트 불러오기를 눌러야 반영됩니다.

  4. ‘발송 방식’이 테스트 모드면 실제로는 안 나갑니다

    홈 화면 상단에 노란 안내문이 보이면 메일 서버(Gmail 또는 Resend) 연결 전 상태입니다. 기록만 남고 실제 발송은 되지 않으니, 실서비스 전 개발 담당자에게 연결을 요청하세요.

  5. 시트는 “링크를 아는 사람이면 볼 수 있는” 상태입니다

    서비스가 시트를 읽으려면 공개 상태여야 합니다. 개인정보·계약 정보·미공개 기밀은 이 시트에 적지 마세요. 구독자 이메일 명단도 가급적 서비스 화면에서 관리하시길 권장드립니다.

  • 시트 제목 칸이 채워져 있고, 쉼표가 있어도 한 셀 안에 들어가 있다

  • 테스트 발송으로 실제 메일함에서 받아봤다 (제목·오타·링크 클릭 확인)
  • ‘발송 방식’ 카드가 테스트 모드가 아니다

구성 및 기술 스택

Next.js 16 + PostgreSQL(Supabase, Drizzle ORM) + Nodemailer. 구글 API 키/OAuth 없이, 공개 공유된 시트의 /export?format=csv 를 가져와 파싱합니다.

[구글 시트] --CSV--> fetchSheetRows() --> syncSheet() --upsert--> [PostgreSQL]
                                                              |
                          tick() 60초마다 --> 발송 대상 판정 --> sendContent()
                                                              |
                                        renderEmail() --> Nodemailer(SMTP) / Resend
                                                              |
                                                        send_logs 기록 (/logs)

테이블: settings(단일행) · contents(시트 행, key로 upsert) · subscribers · send_logs

메일 발송 연결 (테스트 모드 해제)

환경변수 중 하나를 넣으면 자동 인식됩니다. 둘 다 없으면 테스트 모드(기록만 남음).

# ① Gmail / SMTP — 소규모 (하루 약 500통)
SMTP_USER=you@gmail.com
SMTP_PASS=앱비밀번호16자리      # 2단계 인증 후 발급
SMTP_HOST=smtp.gmail.com        # 선택
SMTP_PORT=465                   # 선택
MAIL_FROM=you@gmail.com         # 선택

# ② Resend — 대량 발송 권장 (도메인 인증 필요)
RESEND_API_KEY=re_xxxxxxxxxxxx
MAIL_FROM=news@your-domain.com

발송 시 List-Unsubscribe 헤더가 자동으로 붙어 스팸 분류 위험을 낮춥니다. 도달률을 위해 발신 도메인에 SPF·DKIM 설정을 권장합니다.

배포 · 스케줄러 (중요)

서버가 상시 구동되는 환경에서는 인프로세스 스케줄러가 60초마다 tick()을 수행합니다. Vercel 등 서버리스에서는 이 스케줄러가 항상 살아있지 않으므로 외부 크론이 필수입니다.

  • GET /api/cron 을 1분마다 호출 (Vercel Crons · cron-job.org · GitHub Actions 등)
  • CRON_SECRET 설정 시 ?secret=… 또는 Authorization: Bearer … 필요
  • 외부 크론만 사용할 경우 DISABLE_SCHEDULER=true
  • 배포 환경에도 DATABASE_URL, SHEET_URL, 메일 관련 환경변수를 동일하게 주입

중복 발송 방지: 발송 직전 contents.status를 원자적으로 sending으로 선점하고, 대기열은 settings.last_queue_sent_date로 하루 1건을 잠급니다. 크론이 중복 호출돼도 안전합니다.

발송 판정 로직 요약 
tick()  ← 60초마다 (또는 /api/cron)
 ├─ 1시간 이상 'sending'으로 멈춘 행 → 'failed' 복구
 ├─ 자동 발송(enabled)이 꺼져 있으면 종료
 ├─ syncSheet()                     시트를 다시 읽어 DB upsert
 ├─ 예약 발송: scheduledAt <= now  &&  경과 < 6시간(GRACE_MS)
 └─ 대기열 발송: 오늘이 발송 요일 && 기본시각 ~ +60분 && 오늘 미발송
      → scheduledAt 이 비어 있는 행 중 rowNumber 최소 1건

콘텐츠 식별 key = sha1(제목 + 발송일시). 따라서 제목·발송일시를 바꾸면 새 콘텐츠 = 재발송 트리거입니다. 시트에 id 열을 두면 그 값이 key로 고정되어 더 안전합니다.

보안 상향이 필요할 때

시트 링크 공개가 부담스러우면 src/lib/sheet.ts 의 fetchSheetRows() 하나만 Google Service Account 기반 Sheets API 호출로 교체하면 됩니다. 나머지 코드는 변경이 필요 없습니다. 관리 화면 자체에도 접근 제어(비밀번호/SSO)를 붙이는 것을 권장합니다.
